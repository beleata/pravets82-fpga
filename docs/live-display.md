# Жив текстов екран и клавиатура

Поправка на клавиатурата: при Tk/Windows `event.state & 0x8` означава
Num Lock, а Alt е `0x20000`. Първата версия погрешно отхвърляше и двата
флага, затова истинската клавиатура не работеше при включен Num Lock.
Премахнат е грешният филтър. Регресионният тест покрива комбинациите на
Num/Caps/Scroll Lock; тестът на прозореца вече подава изрично `state=8`
и проверява текста от физическата FPGA. Старият тест със състояние нула
не беше достатъчен. При диагностиката Num Lock на машината беше включен.

Windows приложението е `host/app.py`; стартира се с `start-a2.cmd`.
Изисква новия SRAM дизайн, работещия Pico PIO мост и свободен COM7.
„Свържи“ свързва съществуващата машина, без да я нулира. „Текст“
зарежда нашата малка 6502 програма в RAM и я стартира. Няма BASIC или Apple ROM.

Програмата върху FPGA изчиства екрана, изписва заглавията, чете клавишите
през `$C000`, потвърждава ги с `$C010` и записва символите в екранната RAM.
Windows чете тази RAM и я рисува; няма локално ехо или софтуерна емулация на CPU.
Enter преминава на нов ред, Backspace изтрива, Escape изчиства тестовия екран.
След последния ред тестът се връща на ред 5; това е поведение на демонстрацията.

## Реализация

- Текст: 40×24, двете страници `$0400` и `$0800`, оригинално разпределение
  на редовете, normal/inverse/flashing атрибути и 64 основни символа.
- Адресът на ред е `base + (row & 7)*128 + (row >> 3)*40`.
- CPU достъпите до `$C050–$C057` променят TEXT, MIXED, PAGE2 и HIRES.
  SPI четенето е наблюдение и не превключва тези регистри.
- `$C000–$C00F` връща последния 7-битов клавиш и строб в bit 7.
  CPU достъп до `$C010–$C01F` изчиства строба, запазвайки кода на клавиша.
- FIFO в Windows изчаква свободния едноклавишен регистър; не го презаписва.
  Неподадените клавиши се изхвърлят при загуба на фокус.
- Клавиши се прихващат само от фокусирания екран на приложението. Няма
  глобален keyboard hook. Малките букви стават главни; при BG подредба
  физическите Windows клавиши се превеждат към латинските Apple II кодове.
- RAM има общ CPU read/write порт и отделен синхронен host read порт.
  GUI използва кратка пауза на CPU и копие на екрана в Pico RAM; процесорът
  се пуска преди USB изпращането. Честотата е ограничена до 10 снимки/s.
- Запис през host остава разрешен само при спрян CPU.

Клетките използват Windows Consolas, а не точен растерен Apple character ROM.
HIRES/LORES вече се рисуват; в MIXED долните четири текстови реда остават
видими. Виж `graphics.md`. Транспортът вече е двоичен (`binary-transport.md`).
Екранната RAM и видеорежимът вече се снимат при спрян CPU. Графичното демо
допълнително обозначава завършено рисуване; подробности в `graphics.md`.
Обикновената RAM снимка сама по себе си не гарантира завършен кадър на чужда игра.
Не са реализирани floating bus, Apple видеотайминг, Disk II, звук или paddles.

Основа за адресите и поведението: оригиналният
[Apple II Reference Manual, January 1978](https://apple2history.org/dl/Apple_II_Redbook.pdf).

## Проверки

```powershell
python -m pytest tests -q
python tests/run_machine_spi.py
python host/test_live_text.py --port COM7
python tests/test_app_live.py
```

Последните два теста използват физическата платка и презаписват RAM с теста.
Не записват flash. Затвори прозореца преди командни тестове, за да се освободи
COM7. UI тестът отваря временно приложение, подава Tk клавиши, проверява
получения текст от FPGA и проверява отказа на клавиш при фокус върху друг
контрол. Прави снимка само на прозореца и го затваря.

Потвърдено на 2026-09-26: всички горни проверки минаха, включително 165
символа през няколко физически разпръснати текстови реда и UI въвеждане
`HELLO`, Enter, `Z` при активна BG подредба. Клавишът към нефокусиран екран
беше отхвърлен. Отчети: `build/hardware/live-text.json` и
`build/hardware/a2-window.json`; снимка: `build/hardware/a2-window.png`.

FPGA: 2068 LUT, 446 регистъра, 52/56 BRAM, нула грешки и предупреждения.
Последният timing report дава setup +5.227 ns и hold +0.550 ns.
Пълната проверка на 52 KiB RAM и краткият CPU тест също минаха на новия дизайн.

При изключване на захранването SRAM дизайнът и Pico кодът в RAM се губят;
стартирането само на прозореца не програмира отново устройствата. Командите
за възстановяване са в `cpu.md` и `bring-up.md`.
